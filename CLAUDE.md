# MacSurf

MacSurf is a web browser for Classic Mac OS (8.6–9.2.2, plus Mac OS X 10.0–10.4 via the
same Carbon CFM binary), forked from NetSurf and cross-compiled from Linux, built for real
on hardware via CodeWarrior 8. It has its own native TLS 1.3 stack (macTLS, BearSSL-based)
for direct HTTPS with no proxy in front of it, and an on-device QuickJS (ES2023) engine for
JavaScript — no proxy, no JS offload anywhere; a capability gap gets filled in-house, not
waved off (see DIRECTIVE below).

**Current JS strategy: geometry reads return `undefined`, script size/time are capped.**
`getBoundingClientRect`, `offsetWidth`, and friends deliberately return `undefined` rather
than a real value. Real geometry needs incremental layout; without it, every DOM mutation
costs a full-document relayout, and a page that measures then mutates (a common widget
pattern) either stalls or corrupts its own layout mid-script. `undefined` lets a library
feature-detect around the gap; a plausible wrong number gets trusted and breaks silently
downstream instead — worse. `MACSURF_JS_GEOMETRY` (owned by
`frontends/macos9/javascript/macsurf_qjs.c`) is the switch; flip it back on once
incremental layout exists. "Script runs but reads garbage geometry" is this working as
intended, not a regression.

# DIRECTIVE #1, NEVER BLAME STALE FILES, EVER

This is a repeating, lazy failure mode. You are NOT ALLOWED to consider, suggest, hint, or
imply that:
- the Mac copy of any file is stale, out-of-date, or wasn't extracted from the zip
- CW8 has cached a precompiled prefix or stale .o files
- the user's rebuild was incomplete, missed a file, or didn't pick up changes
- the workflow's transfer step (zip → scp → unpack → CW8 rebuild) failed silently

The user's build IS what they say it is. If the symptoms suggest staleness, the answer is
**always** to research the issue THROUGH THE CODE on Linux and find a real root cause, a
missing #include, a wrong access path, a header collision, a guard mismatch, an
autogenerated file's content, etc., and ship a code-side fix.

If you genuinely believe a previously shipped file may need to be reshipped because the
symptoms continued, just include it in the next zip without commentary about why. Do NOT
narrate the assumption. Do NOT lecture. Just ship the file.

When shipping a fix, the deliverable is:
1. The updated files, zipped with full `browser/netsurf/...` tree preserved
2. A list of files (if any) the user should add to or remove from MacSurf.mcp
3. A list of paths (if any) the user should add to or remove from Access Paths.xml

Nothing else. No "and please verify the Mac unpack worked." No "if this still fails, check
whether CW8 picked it up." No staleness theories.

## Working-tree hygiene

State confusion — unpushed commits, a diverged mirror, a stale claim contradicting a clean
tree — has repeatedly cost time. Run this **preflight at session start and before every
ship/commit**:

- `git status --short` — dirty/uncommitted files (should be empty at rest).
- `git ls-files --others --exclude-standard '*.c' '*.h'` — untracked BUILD files. **Must be
  empty**: a `.c`/`.h` in the CW8 build but not in git means a fresh clone won't build and
  a fix drop can ship a file git never records. This is the single most dangerous drift.
- `git fetch --all -q` then, per remote: `git log --oneline master..$r/master` (remote
  ahead → divergence, investigate before pushing); `git log --oneline $r/master..master`
  (you ahead → unpushed, push it).

Commit each fix as you go (individually revertable) and push immediately — don't hold
commits for hardware verification. If a prose claim anywhere disagrees with what these
commands report, the commands win; fix the prose.

## Commands

- **`gcc -fsyntax-only -std=c89 -pedantic -Dinline= -Ibrowser/netsurf/frontends/macos9/shims -Ibrowser/netsurf/frontends -Ibrowser/netsurf/include -Ibrowser/netsurf -include stdbool.h <file>`**
  — Linux syntax cross-check before shipping. **Only works on files that don't reach
  `macos9.h`.** Anything that includes it (`main.c`, `window.c`, most of
  `frontends/macos9/*.c`) fails fast with dozens of unknown-Carbon-type errors plus a fatal
  missing-header error — Carbon isn't available on Linux. Use it for isolated helper files
  only; an error count from a Carbon-touching file says nothing about the Mac build.
- **`make check-c89`** / **`make check-macdefault`** (in `harness/`) — `check-c89` catches
  CW8's one C89 rule `-std=gnu99` can't see (statements before declarations in a block);
  `check-macdefault` compiles the JS glue with the Mac's actual switch config (the harness
  normally forces switches ON that ship OFF). Run before any drop touching a
  `MACSURF_JS_*` switch.
- **`./forclaude/ship.sh <fixnum> [repo-relative-path]...`** — the whole round in one
  command: push → CodeWarrior **Bring Up To Date**, then launch → error check → StuffIt
  → `.sit` on macfiles as `MacSurf<fixnum>.sit` (never overwrites; collisions get `-2`,
  `-3`). Drives the Mac's GUI apps over SSH via AppleScript, and refuses to package if
  CodeWarrior reports any message. With no paths it just rebuilds and relaunches. It does
  **not** verify anything on hardware — that stays the maintainer's call. Full mechanics,
  prerequisites and failure modes: `docs/build/automated-ship.md`.
- **`./forclaude/drop-to-imac.sh <fixnum> <repo-relative-path>...`** — push only; what
  `ship.sh` calls for its first step, and the right tool for getting files onto the Mac
  without a build. Verified: CR-converts, stamps a future mtime, scp's each file to the
  iMac, verifies size + CR/LF on the far side (LF must be 0 or CodeWarrior chokes). Never
  CR-convert or mtime-stamp by hand.
- **Bring Up To Date before Run.** `Run` silently declines to compile while the built
  app is running, so the pipeline explicitly sends CodeWarrior's Bring Up To Date command
  immediately before `Run` rather than treating `Run` as the build. Confirm the built
  binary changed after a source drop; "binary mtime unchanged" is the alarm, not a note.
  See `docs/build/automated-ship.md` §3.2.1; project-file adds/removes over AppleScript
  are §3.7; bisecting on hardware is `docs/build/hardware-bisect.md`.
- **`tools/ship_fix.sh`** — retired-not-deleted fallback (tars, CR-converts, scp's to the
  OS 9 laptop route). Only ships the files you name — a probe left in an earlier round
  stays live on the target until you explicitly re-ship that file.

## Architecture and constraints

- **Components**: `browser/` (NetSurf fork + `frontends/macos9/`), `macTLS/` (native TLS,
  nested project folded into the build). No proxy directory exists in this tree and none
  should be reintroduced — HTTPS goes straight from the Mac through macTLS.
- **Tabs are unimplemented, not disabled** — no tab fields on `struct gui_window`, no
  `BW_CREATE_TAB` handling; `macos9_window_create` always opens a new window. Multi-window
  is real; tabs are not.
- **`TARGET_API_MAC_CARBON` must be defined before the first `<MacTypes.h>` include** in
  `macsurf_prefix.h`. `MacTypes.h` pulls in `ConditionalMacros.h`, which computes the
  Carbon triplet from this define and guards itself against reprocessing — set it later and
  the binary compiles non-Carbon against Carbon headers (survivable on OS 9's CarbonLib,
  fatal on OS X).
- **`'carb'` resource in `MacSurf.rsrc` is mandatory** — without it CFM treats the binary
  as classic PEF, CarbonLib never engages, and any `*InContext` OT call crashes at a fixed
  address inside OTClientLib.
- **No preemptive threads anywhere** — OS 9 is cooperative; the UI loop is `WaitNextEvent`,
  blocking OT calls yield via `OTUseSyncIdleEvents` + a notifier on `kOTSyncIdleEvent`.
- **JS engine is QuickJS (ES2023), not Duktape** — Duktape is not in the tree at all.
- **Target hardware**: Power Mac G3/G4, Mac OS 9.1–9.2.2, 128–384 MB RAM depending on site
  weight. **Do not target OS X only** — Carbon must keep running on OS 9.

## Library port audit checklist

When auditing a new C99 library file for CW8 / strict C89 compatibility, grep for:
- `inline` keyword; `//` line comments (start-of-line AND trailing; exclude URLs inside
  `/* */` block comments)
- C99 designated initializers (`^\s*\.\w+\s*=`) — count instances **per file**, not just
  file count (one file has had 47 in a single pass)
- For-scope declarations: integer types AND **pointer-type variants**
  (`for (TYPE *NAME = ...)`) — pointer-type for-scope decls have been undercounted before
- `restrict` keyword, compound literals
- `__VA_ARGS__` variadic macros (CW8 supports this specific one as a pre-C99 extension —
  not itself a violation, but check every use site)
- `long long`, variable-length arrays, flexible array members, forward enum declarations
- `__attribute__` / `__builtin_*`; `snprintf` / `vsnprintf`; `%zu` / `%zd` printf formats
- `<iconv.h>`, `<errno.h>`, `<strings.h>`, `<sys/types.h>` and other POSIX headers
- **GNU union casts** — `(union_type)0` or `(typedef_name)expr` where the typedef resolves
  to a union. Standard C89 forbids casting to a union type.
- **Union initializers using designated syntax** — `{.field = value}` for a typedef'd union
  looks identical to a struct designated init in a grep pass. C89 union initializers must
  be positional (`{value}`, first member only).
- Build-time codegen (`gperf`, perl scripts, `.inc` files included from `.c` files)
- Existing MacSurf stubs in `frontends/macos9/<libname>/` that will conflict with the real
  headers once ported

## Adding new .c files

1. Cross-check it on Linux first (see Commands above) — catch a C89/CW8 violation before
   it costs a round trip to the Mac.
2. **Do NOT edit `MacSurf.mcp` and do NOT include it in a drop** — name the new file(s)
   plainly in the handoff instead. The user maintains the project file list on the Mac
   side through the CW8 IDE; a Linux-edited `.mcp` will clobber their local changes.
3. If the new file is a libcss property (`p_<name>.c`/`s_<name>.c`), follow the template in
   `browser/libcss/CLAUDE.md` → "Adding a native property" rather than improvising the
   multi-file wiring.

- `transition`/`animation` are not parsed at all — stripped from the CSS text by a

- `height` family, `flex-basis`, `table-layout: auto`, and grid `minmax()`/`fit-content()`
  tracks don't yet accept `min-content`/`max-content`/`fit-content` (`width` already does).
- `unicode-bidi`, `writing-mode`, `break-*`/`page-break-*`, `orphans`/`widows`,
  `fill-opacity`/`stroke-opacity` are parsed and correctly dropped — no bidi engine,
  paginator, or SVG paint pipeline consumes them. Not bugs.

## Cross-cutting gotchas

Repo-wide, or things you can hit before opening any subsystem file. Subsystem gotchas live
in that subsystem's own `CLAUDE.md`: `frontends/macos9/`, `frontends/macos9/javascript/`,
`browser/libcss/`, `browser/netsurf/content/`, `macTLS/`.

- **Harness false-green trap**: never add `-w` to a check target — it suppresses the
  warning the gate exists to catch, and prints "OK" while testing nothing. Assert
  counts/behavior, not a boolean.
- **The Linux JS/CSS harness (`harness/`) force-includes no prefix file** — anything
  `macsurf_prefix.h` provides is missing there, and its stub generator will invent a
  function for a missing **macro** it doesn't recognize (`N_ELEMENTS` once became
  `void N_ELEMENTS(void){}`, silently making libcss reject every pseudo-class selector).
  A harness-only bug should make you suspect the stub generator first.
- **CSS in the harness needs `media.type = CSS_MEDIA_SCREEN` AND sheets appended with
  `"screen"`** or the cascade silently yields initial values with no error.
- **Diagnosing "the page renders wrong," cheapest first:** content even in the DOM (zero
  children usually means script deleted it) → script skipped for size/timing out (check its
  skip/abort log line) → reproduce in `harness/reconvert_harness` → only then suspect CSS.
- **Diagnostic log lines must be prefixed `LIFE `** to survive the release build's
  failures-only filter — see `frontends/macos9/CLAUDE.md` for the mechanism.
- **"Page hangs mid-load" / a fetch never completes** has two distinct root causes on
  file — check both `browser/netsurf/content/CLAUDE.md` (fetch lifecycle) and
  `frontends/macos9/CLAUDE.md` (fetcher self-free rule).
- **JS switches by name**: `MACSURF_JS_GEOMETRY`, `MACSURF_JS_MAX_BYTES`, and
  `MACSURF_JS_TIMEOUT_MS` are all owned by `javascript/macsurf_qjs.c` — see
  `frontends/macos9/javascript/CLAUDE.md` before changing any of them.
