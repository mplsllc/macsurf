# browser/libcss — CSS parser + cascade

Ported to C89/CW8. This is the CSS engine; `browser/netsurf/content/handlers/css/` is the
MacSurf-specific preprocessor bridge in front of it (see that directory's own notes if
present, or `browser/netsurf/content/CLAUDE.md`).

## Lexer

- **Custom properties (`--foo`) need the keystone fix in `CDCOrIdentOrFunctionOrNPD`**
  (`src/lex/lex.c`). The original CSS2.1 grammar allowed one leading dash (vendor
  prefixes); without a branch that also accepts a SECOND leading dash before checking
  `startNMStart`, the tokenizer splits `--foo` into two tokens and every `var()`/custom
  property in a page drops at tokenization, before any parser logic runs.

## Adding a native property

This is a mechanical multi-file add — grep the codebase for a recent example property
(e.g. one added via the bit-packed array, and one added via the scalar-tail pattern below)
and follow its shape file-by-file rather than improvising:

- `properties.h` — new `CSS_PROP_*` enum value (+ any new value enum)
- `computed.h`/`computed.c` — the accessor
- storage: **prefer a self-aligning scalar field appended at the END of
  `css_computed_style_i`** (see the struct rules below) over the bit-packed `bits[]` array
  — the bit-packed array has historically filled up, and appending at the end is the
  proven-safe pattern regardless. Only use a `bits[]` slot if one is actually free; extending
  the array to a new word is a structural change to a struct the arena interner `memcmp`s
  wholesale, and needs its own audit pass first.
- `propstrings.h`/`.c` — the property name and any new value strings, kept in
  enum⇄string-array lockstep
- a new `p_<name>.c` parser + an entry in the `src/parse/properties/properties.c` handler
  table (append at the end of the list) + the matching decl in
  `src/parse/properties/properties.h`
- a new `s_<name>.c` cascade handler + an entry in `src/select/properties/properties.h`'s
  PROPERTY_FUNCS table
- **`s_dispatch.c`'s `prop_dispatch[]` table** — append the entry, second field is the
  inherited flag (0/1), keep the count in sync with `CSS_N_PROPERTIES` or you get an
  out-of-bounds read on the dispatch table at the new property's index (crash signature:
  unmapped-memory exception with PC at a garbage address). **`dispatch.c` no longer exists
  in this tree — `s_dispatch.c` is the only file that defines `prop_dispatch[]`; do not try
  to ship or edit a `dispatch.c`, it isn't there.**
- finally, wire the actual CONSUMER in redraw/layout — everything above just gets the value
  parsed and cascaded, it renders nothing by itself.

New `p_*.c`/`s_*.c` files need to be added to the CW8 project by the user — don't edit
`MacSurf.mcp`, just name the new files in the handoff.

## `css_computed_style_i` struct rules

The arena interner (`src/select/arena.c`) does a raw `memcmp` over the whole
`css_computed_style_i` struct to find duplicate computed styles and deduplicate them.
This makes the struct's byte layout load-bearing, not just its logical contents:

- **Every scalar field in `_i` must be `int32_t`-sized so it self-aligns.** A sub-4-byte
  scalar between two `int32_t` fields forces the compiler to insert padding, and different
  cascade code paths can leave that padding with different garbage (a fresh `calloc` zeroes
  it, but a compose-then-modify path may carry source padding through). `memcmp` then
  treats two logically-identical styles as different, the arena interns a duplicate, and
  the duplicate gets destroyed while something still holds a pointer to it — a
  use-after-free in `css_computed_style_destroy`, not a cascade bug, and the crash log will
  look nothing like a struct-layout issue.
- **Never add a multi-byte, non-bit-packed field to `_i` whose value isn't byte-identical
  across every cascade path that can produce a logically-equal style** — pointers,
  variable-length arrays, anything with per-path divergence. Those belong on the OUTER
  `css_computed_style` struct instead, with a dedicated `arena__compare_*` function
  registered in `css__arena_style_is_equal` for logical (not byte) comparison. Bit-packed
  flags in the `bits[]` words are fine because every cascade path writes them
  deterministically.

## C89

- **Casting to a union type is a GNU extension, illegal in C89.** `(css_fixed_or_calc)0`
  won't compile under CW8. Use a local compound-statement workaround instead: open a brace,
  declare a union-typed local, assign `.value` (or the relevant member), use the local, close
  the brace (see `src/select/autogenerated_destroy.inc` for the pattern). This is easy to
  miss with a simple grep for `(css_` since it looks like an ordinary cast.
- **A relative `#include "select/calc.h"` from within a header that itself lives under
  `select/` fails on CW8** — it can't traverse an access path from inside a header. Use the
  bare filename (`"calc.h"`) when the target is in the same directory as the includer.

- **Fixed-point math giving a wrong answer** — this file's own `include/libcss/fpmath.h` is

  hazard itself is documented in the frontend's CW8/C89 build-hazard list.
- **`CSS_NOMEM` firing mid-cascade** — usually the Carbon partition size, not a leak or a
