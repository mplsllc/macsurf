## 1. Dead / Unused Code

### 🔴 `dispatch.c` is a stale byte-identical duplicate of `s_dispatch.c`
**Files:** `browser/libcss/src/select/dispatch.c` (670 lines), `browser/libcss/src/select/s_dispatch.c` (670 lines)

The two files are semantically identical — `diff -w` shows zero differences. Only whitespace (tabs vs. spaces) distinguishes them. Only `s_dispatch.c` is compiled on the Mac. This is a **documented gotcha** in CLAUDE.md: every CSS property add requires manually editing BOTH files in lockstep. A miscount or drift silently corrupts unrelated properties in the cascade.

**Fix:** Delete `dispatch.c` from the tree. Git has the history. The CLAUDE.md instructions to "ship both" should become "only `s_dispatch.c` exists."

### 🟡 `macos9_extra_stubs.c` — completely dead
**File:** `browser/netsurf/frontends/macos9/macos9_extra_stubs.c` (7 lines)

Contains a single function `macos9_extra_stub_init(void)` that is **never referenced anywhere** in the entire tree (grep confirmed). This file compiles and links a symbol nothing calls.

**Fix:** Delete the file and remove from `MacSurf.mcp`.

### 🟡 `macos9_wheel.c` — intentional no-op, never called
**File:** `browser/netsurf/frontends/macos9/macos9_wheel.c` (71 lines)

The entire file is a history comment explaining that `kEventMouseWheelMoved` is unavailable in CarbonLib (caused an illegal-instruction crash). Its only function `macos9_wheel_install()` is **never called** anywhere.

**Fix:** Either delete the file (the history is in git), or keep as documentation. If kept, add a one-line comment at the top stating it's intentionally dead.

### 🟡 `js_stub.c` — compiles to zero effective code
**File:** `browser/netsurf/frontends/macos9/js_stub.c` (148 lines)

Every function body is gated on `#ifndef WITH_QUICKJS`. `WITH_QUICKJS` is always `1` (set in `macsurf_prefix.h:385`). CLAUDE.md notes: "inert while WITH_QUICKJS is defined."

**Fix:** Add `#ifndef WITH_QUICKJS` / `#error "js_stub.c should not be compiled with QuickJS"` / `#endif` at the top so it fails loudly if accidentally compiled. Or remove from `MacSurf.mcp`.

### 🟡 `autogenerated_computed_v2.h` — orphaned
**File:** `browser/libcss/src/select/autogenerated_computed_v2.h` (311 lines, 11.6 KB)

**Zero includers** anywhere in the entire tree. This is a generated file that nothing references — likely a v2 experiment that was abandoned.

**Fix:** Delete the file.

### 🟡 `shims/ns_strings.h` — identical duplicate of `shims/strings.h`
**File:** `browser/netsurf/frontends/macos9/shims/ns_strings.h`

Byte-identical to `strings.h` in the same directory. One is redundant.

**Fix:** Delete `ns_strings.h`. If anything includes it by that name, add a forwarding include or update the includer.

### 🟡 3 duplicate shim header pairs
**Files:** `shims/time.h` / `shims/ns_time.h`, `shims/unistd.h` / `shims/ns_unistd.h`, `shims/endian.h` / `shims/ns_endian.h`

Each pair differs only in the comment line. They exist because code includes both `<time.h>` and `<nsutils/time.h>`, and the CW8 access path resolves both to the `shims/` directory.

**Fix:** Make one include the other with a forwarding guard, or consolidate to a single file with both guards.

### 🟡 `#if 0` block in `cssh_css.c` — legacy grid-column rewriter
**File:** `browser/netsurf/content/handlers/css/cssh_css.c:1247-1441`

A ~193-line dead function `macsurf__rewrite_grid_column_legacy()`. Comment says "retained inline-disabled for reference." Git already retains it.

**Fix:** Delete the block.

### 🟢 `MacSurf.mcp` references files that no longer exist
**File:** `browser/netsurf/frontends/macos9/MacSurf.mcp`

References `content/handlers/html/css.c` and `content/handlers/html/font.c`, which were renamed to `html_css.c`/`html_font.c` in commit `a2082633`. Also references `dispatch.c` instead of `s_dispatch.c`.

**Fix:** Update the `.mcp` on the Mac side (CW8 IDE). Low urgency — the Mac build has its own copy.

## 2. Duplication

### 🔴 `dispatch.c` / `s_dispatch.c` (see above)

### 🟡 Fetcher code duplication — 9 confirmed patterns
**Files:** `macos9_tls_fetcher.c` (3,707 lines), `macos9_http_fetcher.c` (1,951 lines)

Both fetchers are parallel implementations of the same HTTP client. Nine confirmed duplications identified by the audit agent:

1. **Line scanner** — `mfs_find_line` (http) vs `find_line` (tls): same CRLF search
2. **Header parser** — `mfs_parse_headers` vs `parse_headers`: identical walk including the text/plain→text/html relabel, Content-Type/Length/Encoding, Connection, Location, Set-Cookie capture, 3xx redirect + terminal-URL handling
3. **Cookie request header build** — same `cookie_hdr[6144]`, same `urldb_get_cookie`, same assembly
4. **Sec-Fetch/Origin synthesis** — byte-identical `synth[512]` three-branch block
5. **Request template `sprintf`** — same POST/GET layout
6. **REQ summary log** — same format string (comments say "Mirrors the HTTPS fetcher")
7. **Disk-cache-hit fast path** — nearly verbatim (TLS comment: "Mirrors the HTTP fetcher")
8. **Tracker/ad blocklist gate** — same host-extract-and-check
9. **Set-Cookie + login POST cache-skip** — same store + clear + skip dance

**Note:** User-agent logic is NOT duplicated — `macos9_user_agent_for_host()` was already unified into `macos9_fetch.c` (fixes368).

**Fix:** Extract shared functions into `macos9_fetch.c`:
- `macos9_build_request_headers()` — header assembly
- `macos9_capture_response_set_cookie()` — Set-Cookie storage
- `macos9_find_header_line()` — CRLF scanner

### 🟡 Magic buffer sizes scattered as literals
**Files:** Both fetchers

`65536`, `8192`, `6144`, `2048`, `4096`, `1024` appear as raw numbers. The TLS fetcher has `#define` constants for some; the HTTP fetcher hardcodes the same values inline.

**Fix:** Define in `macos9_fetch.h`:
```c
#define MACSURF_HDR_BUF_MAX      65536
#define MACSURF_READ_CHUNK       8192
#define MACSURF_COOKIE_HDR_CAP   6144
#define MACSURF_CALLER_HDRS_CAP  2048
#define MACSURF_NO_PROGRESS_TICKS 240
```

## 4. Structure & Organization

### 🟡 ~652KB of embedded binary image data in C headers
**Files:** `loader_frames_data.h` (7,012 lines, 527KB), `toolbar_icons_data.h` (953 lines, 70KB), `about_logo_data.h` (569 lines, 43KB), `manager_icons_data.h` (167 lines, 12KB)

Raw hex arrays compiled into the binary. These are effectively resources.

**Fix:** For the OS 9 build, move to resource fork (`'cicn'`/`'PICT'` resources) generated at link time. For the harness, load from files at runtime. The `png_to_mac_icon_rez.py` tool already exists.

### 🟡 Shims directory name is misleading
**Directory:** `browser/netsurf/frontends/macos9/shims/`

The `.c` files (`mac_dirent.c`, `mac_file_io.c`, `mac_iconv.c`, `mac_stat.c`, `mac_time.c`) are **real, complete implementations** of POSIX APIs on top of Carbon File Manager — not stubs. They're 150-350 lines each with full error handling. The `.h` files in the same directory ARE stubs/shadow headers.

**Fix:** Rename `shims/` → `compat/` for the `.c` files. Move the `.h` shadow headers to a `stubs/` directory.

### 🟡 `misc_stub.c` `stat()` conflicts with `shims/mac_stat.c`
**File:** `misc_stub.c:285` defines `stat()` returning -1. `shims/mac_stat.c` provides a real `stat()` implementation. Which one the linker picks depends on `MacSurf.mcp` order.

**Fix:** Delete the stub `stat()` from `misc_stub.c`; the real implementation in `shims/mac_stat.c` should be the only one.

### 🟢 `lodepng` is vendored third-party code in the frontend directory
**File:** `browser/netsurf/frontends/macos9/lodepng.c` (7,244 lines), `lodepng.h` (2,188 lines)

The only vendored dependency living directly in the frontend directory. All other dependencies live in `browser/lib*/`.

**Fix:** Move to `browser/third_party/lodepng/` or `browser/vendor/lodepng/`.

### 🟢 `css/css.h` and `image/image.h` stub headers have divergent signatures
**Files:** `browser/netsurf/frontends/macos9/css/css.h`, `browser/netsurf/frontends/macos9/image/image.h`

`image/image.h` declares `unsigned char image_bitmap_plot(...)` while the real header returns `bool`. If the real header is ever included in the same TU, the signature mismatch causes subtle bugs.

**Fix:** Audit stub signatures against real headers. Add a build-time check or comment noting which signatures must stay in sync.

## 5. Error Handling & Robustness

### 🔴 TLS fetcher: `post_body` leak on setup failure
**File:** `browser/netsurf/frontends/macos9/macos9_tls_fetcher.c:3478-3520`

`macos9_https_setup` allocates `c->post_body` at line 3478. If `nsurl_get_component(u, NSURL_HOST)` later returns NULL, the function unrefs `c->url` and returns NULL **without freeing `c->post_body`**. The slot is left `HS_IDLE` and the next setup `memset`s it, permanently losing the pointer.

**Fix:** Add `free(c->post_body); c->post_body = NULL;` before the error return.

### 🟡 HTTP fetcher: `realloc` loses old pointer on failure
**File:** `browser/netsurf/frontends/macos9/macos9_http_fetcher.c:1354`

```c
c->h_buf = realloc(c->h_buf, nc);
if (c->h_buf) c->h_cap = nc;
```

Classic pattern: on `realloc` failure, `c->h_buf` is overwritten with NULL and the original allocation is lost. The TLS fetcher has a correct temp-variable pattern at line 2759.

**Fix:** Use a temp variable:
```c
char *nb = (char *)realloc(c->h_buf, nc);
if (nb) { c->h_buf = nb; c->h_cap = nc; }
```

### 🟡 TLS fetcher: `malloc` without NULL check
**File:** `browser/netsurf/frontends/macos9/macos9_tls_fetcher.c:2752`

`c->hdr_buf = (char *)malloc(c->hdr_cap);` — not checked. The `realloc` at line 2759 would crash if the initial malloc failed. The `post_body` malloc at line 3478 IS checked, so this is an inconsistent pattern within the same file.

**Fix:** Add NULL check after the malloc.

### 🟢 Error handling audit summary
The codebase is **unusually diligent** about allocation checks overall. The audit agent confirmed: every other `malloc` in `main.c`, `window.c`, and the fetchers is NULL-checked. The genuine gaps are the three above.

## Methodology

This audit was performed on 2026-08-05 against branch `3.0` (clean tree, HEAD at fixes1039 range). Three parallel agents explored:
- **Frontend agent:** All 50+ `.c`/`.h` files in `browser/netsurf/frontends/macos9/` — dead files, large functions, duplication, magic numbers, error handling, unused includes
- **Content/libcss agent:** libcss autogenerated files, stub/shadow headers, `cssh_css.c` structure, content handler patterns, `#if 0` blocks, resource leaks
- **Build/macTLS agent:** Failed with API error (partial — only git tracking checks completed)

Direct analysis supplemented with: line counts, `diff` comparisons, malloc/realloc audit, section-header mapping of `macsurf_qjs.c`, `DROP_PROPS` table inspection, and embedded data size measurement.

Total: **24 findings**, 4 high, 13 medium, 7 low.
