# MacSurf fixes beyond upstream NetSurf

Running inventory of MacSurf work that upstream NetSurf (stock `netsurf-browser`)
does not have. This is the reference list for porting MacSurf improvements to
other NetSurf-derived trees (e.g. the Besra branch, which tracks this under its
own `plan.md` MacSurf CSS-parity section).

Each entry: what, where, commit ref, and why upstream lacks it. Append a new
entry per fix round — never edit an old entry (history must stay a faithful
log).

---

## fixes1159 + fixes1184 — calc() resolution for all length properties

- **What:** `calc()` resolves for margins, padding, borders, height, min/max
  height/width, letter-spacing, word-spacing, text-indent, top/right/bottom/left.
  Previously only `width` had a working path (`css_computed_width_px`); every
  other property dropped the declaration to 0px.
- **Where:** `browser/libcss/src/select/properties/helpers.c` (5 cascade
  helpers), `select/unit.c` (CSS_UNIT_CALC resolution),
  `select/autogenerated_computed.h` (per-style side-slot table
  `macsurf_calc_expr[28]` + fixed property->slot mapping
  `css__calc_slot_for_prop`), `select/arena.c` (compare), `select/computed.c`
  (compose/clone carry).
- **Commits:** `04cf7fa68` (fixes1159), `813456f65` (fixes1184).
- **Why upstream lacks it:** upstream libcss has the full machinery (calc parse
  bytecode, `css_calculator`, `css_fixed_or_calc`) but only wires it through
  width via `css_computed_width_px`; the shared cascade helpers
  (`css__cascade_length*`) contain the same `TODO: Skip unit` stubs as the
  fork, so calc silently resolves to 0 everywhere else.
- **Design note (the part worth replicating):** fixes1159 first bit-cast the
  interned expression `lwc_string *` into the 32-bit `css_fixed` length slot.
  That is broken on any 64-bit target (pointer truncation - ASan SEGV in
  `css_calculator_calculate`) and was misresolving on the Mac. Never store a
  pointer in `css_fixed`. fixes1184 replaced it with a fixed per-property
  side-slot table in the outer `css_computed_style`, slot number in the length
  field, carried through compose/clone and compared in
  `css__arena_style_is_equal`. A tree that is willing to change layout call
  sites (Besra's `_px` getter plan) can instead extend `css_fixed_or_calc`
  storage per property, which is the upstream-style design.

## fixes1185 — calc() in the margin and padding shorthands

- **What:** `margin: 10px 0 10px calc(30px + 10px)` and
  `padding: calc(10px + 5px)` now work. Before, the shorthand silently dropped
  the calc component and re-distributed the remaining sides (margin-left
  became 0). The border shorthands already handled calc via
  `css__parse_border_side_width`.
- **Where:** `browser/libcss/src/parse/properties/margin.c`,
  `parse/properties/padding.c`. Calc sides are parsed into temporary styles
  (the property a side belongs to depends on the final side count, which is
  only known after the parse loop) and re-emitted from the temp bytecode
  (`[OPV][unit][snum]`) with the correct property once the count settles.
- **Commit:** `4e3db9928`.
- **Why upstream lacks it:** upstream's `css__parse_unit_specifier` accepts
  only DIMENSION/NUMBER/PERCENTAGE and has no calc branch, and the margin/
  padding shorthand parsers call straight into it. Verified against
  `netsurf-browser/libcss` master (2026-08-12) - the gap is upstream's, not a
  fork regression.

## css__stylesheet_string_get bounds-check bug

- **What:** `if (string_number > sheet->string_vector_c) return CSS_BADPARM;`
  is an off-by-one (`>` should be `>=`), so an out-of-range index can pass and
  dereference `string_vector[string_number]` out of bounds. It also returns
  BADPARM without touching `*string`, so callers that do not initialize the
  out-pointer read garbage on the failure path.
- **Where:** `browser/libcss/src/stylesheet.c`.
- **Why upstream lacks it:** not checked against upstream master yet; if the
  same code exists upstream it is the same latent bug. Worth a
  grep-and-patch round on any tree.

## How to keep this file current

- After every MacSurf fix round that produces an upstream-relevant change,
  append an entry above (never rewrite history).
- "Upstream-relevant" = the stock `netsurf-browser` trees do not have the
