### fixes1068 — the form-control fallback

`layout.c` sizes replaced elements in three branches. The last is commented
*"form control with no object"* and assigns **1em × 1em**. Upstream NetSurf
never reaches it with an image: it has no deferred loading, so every `<img>`
owns an object by layout time. MacSurf **added** lazy loading (fixes738/932),
creating a case upstream does not have — an `<img>` with no object yet. If its
URL also misses the imgdims memo (fixes929 fills `obj_w` on a hit, taking the
aspect-preserving branch), it fell through and got a 1em **square** regardless
of its real shape.

Reproduced in the harness at 993px — identical markup, only the sizing hints
differ:

| case | markup | IMG box | row height |
|---|---|---|---|
| A | `<img loading="lazy">` only | **15×15** | **19** |
| B | `+ width="48" height="48"` | 48×48 | 48 |
| C | `+ CSS width/height` | 48×48 | 48 |

Now gated on `b->gadget != NULL`; a replaced element still awaiting content
reserves 0×0 and takes its true size when the object lands.

### fixes1069 — crypto RNG

`crypto.getRandomValues` and `crypto.randomUUID` shipped on a clock-seeded
xorshift (fixes717, so scripts touching `crypto.*` would run rather than
throw). Its own comment said it was *"NOT cryptographic-grade"* and pointed at
macEntropy.

This was **not a missing feature but a wrong answer** — the failure class this
engine has paid for repeatedly. WebGL/WebRTC are absent, so pages
feature-detect around them; here the API was present and answered confidently
with predictable bytes. A page minting a session token, CSRF nonce or v4 UUID
had no way to tell.

Both now draw from macEntropy — the SHA-256 pool already seeding every TLS
handshake, fed by OT packet jitter, key/mouse timing and a seed file persisted
across launches, with a statistical self-test. It was linked and
hardware-verified the whole time; nothing outside the handshake consumed it.
New `OSTLS_RandomBytes(out, len)` extracts under its own domain-separation tag.

### 3.2 CORRECTION TO PROJECT STATE — the XenForo cascade is broken open

`CLAUDE.md` records the XenForo failure as a **total cascade**: preamble throws
→ jQuery/Sizzle throws → `core-compiled.js` dies on `jQuery.support` →
`XF.Element` never registers → *every* dependent module throws.

**That is no longer what happens.** This log shows every later bundle loading
and running after the preamble failure:

```
vendor-compiled.js      core-compiled.js      lightbox-compiled.js
action.min.js           message.min.js
```

Only `preamble.min.js`'s own tail is lost. The cascade entry in `CLAUDE.md` is
stale and should be rewritten — the fixes846/878/989 DOM work evidently closed
the downstream links, leaving **one** failing function.

### 3.3 That one function, root-caused

```js
function a(){ let d=f.body;
              d||(d=f.createElement("body"), d.dataset.fake="true", f.body=d);
              return d }

hiddenscroll:()=>{ var d=a();
                   const b=f.createElement("div"); …
                   d.appendChild(b);
                   d=b.offsetWidth===b.clientWidth;   // d reassigned to a bool
                   b.parentNode.removeChild(b);       // ← throws
                   c(); return d }
```

`preamble.min.js` is loaded in `<head>`, so `document.body` is null. XenForo
handles that by building a **detached** `<body>` and appending the probe div
into it. `b.parentNode` then reads back **null**.

So the remaining defect is narrow and testable: **`appendChild` into a detached
element does not set the child's `parentNode`.** Harness Test 46 covers
`removeChild` clearing `parentNode` and `appendChild` moving rather than
copying, but not the detached-parent case.

**Why it matters beyond one exception:** the `has-js` class swap lives in the
same file —
`b.replace(/(^|\s)has-no-js($|\s)/,"$1has-js$2")`. The Abyss theme gates its
real nav and editor styling behind `.has-js`. That is the documented cause of
the grey/blank nav and the unstyled reply box (#204), i.e. the "page looks
broken" complaints are downstream of this single `parentNode` answer.

### 3.4 #226 — inconclusive, and honestly so

`img-aspect: 0 hits` on this load. **This is not proof the bug is fixed.**
fixes1068 makes unsized lazy images 0×0, and the probe requires `dw > 0`, so it
is now blind to exactly those boxes. Separately the probe reads natural size via
`content_get_width(box->object)`, so it can never see an image with no object.

What is established:
- 68kmla avatars are natural **48×48** and carry `width="48" height="48"` —
  they are case B and lay out correctly. **The avatars were never the 9×21
  images.**
- The 13 distorted 64×64 images are not on the front page; they are smilies or
  node icons on a **thread** page.
- The aspect asymmetry in `layout_get_object_dimensions` (a `max-width` clamp
  that does not re-derive the other dimension, unlike the both-AUTO branch
  which does) is **probably spec-correct** per CSS 2.1 §10.4 when the height is
  author-specified. Deliberately not "fixed" — that would trade a real bug for
  a spec violation.

## 4. Method notes earned this round

- **Two harness false-greens were found and closed** — fixes1062
  (`css_hint_init` never called → segfault on any presentational attribute) and
  fixes1066 (`foreground_images` false → every `<img>` at w=0). The second
  produced a box tree *identical to #226's reported bug*; a product defect was
  nearly diagnosed from a harness artefact.
- **A probe must be able to observe the mechanism it is testing.** The fixes1067
  probe reads natural size through `box->object`, making it structurally blind
  to the no-object case it was built to investigate. Another hardware round with
  it would have returned nothing.
- **Do not conclude from truncated output.** `grep NAV | head -8` on a 735-line
  log produced a confident and wrong "the site was never loaded".
- The harness box dump goes to **stderr**; `2>/dev/null` silently discards it.

## 5. The plan from here

Ordered by value, with the evidence each rests on.

### Tier 1 — highest value, root-caused, ready to build

1. **`appendChild` into a detached element must set `parentNode`** (§3.3).
   Root-caused from the real bundle. Unblocks `has-js`, which gates XenForo's
   nav and editor styling (#204) on both 68kmla and tinkerdifferent. Harness
   Test 46 extends naturally to cover it. **This is the recommended next job.**
2. **#226 remainder** — needs one **thread**-page load to catch the 64×64
   images; the front page does not contain them.

### Tier 2 — structural, unblocks multiple issues

3. **#262** — `innerHTML` GET still returns `textContent`; `outerHTML` is a
   synthesized string with no setter. The known remaining serializer hole.
4. **#265** — `getComputedStyle` / `getBoundingClientRect`. Geometry must not
   return before the synchronous-layout pass or measure-then-mutate widgets
   damage pages (the fixes1022 lesson).
5. **`min-content`/`max-content`/`fit-content` solver** — prerequisite for
   `table-layout: auto` and correct flex/grid shrink-to-fit.

### Tier 3 — known gaps with real page impact

6. **`matchMedia` answers false to every query** (the `WANT` channel, fixes1039)
   — every responsive branch takes the same path regardless of viewport. Top
   candidate among the things we fake.
7. **MutationObserver / ResizeObserver `.observe` is a no-op** — a page waiting
   on one waits forever.
8. **`<script type="module">` is silently dropped** in `script.c`, with no log
   line at all.
